# Сайт «Северный Уралец» — универсальная статическая версия

Этот архив — готовый сайт-каталог рулонных штор. Он работает:
- **на любом хостинге** (Beget, Timeweb, reg.ru, Netlify…) — загрузите файлы в папку сайта;
- **даже просто на компьютере** — распакуйте архив и дважды щёлкните по `index.html`.

Внутри:
- `index.html` — главный файл сайта (единственная «страница»: главная, каталог,
  карточки товаров, о компании, контакты открываются внутри неё мгновенно,
  адрес меняется после решётки, например `сайт.ru/#/catalog`)
- `_next/` — скрипты, стили и шрифты (техническая папка, не трогайте)
- `images/` — фотографии товаров (оптимизированные WebP)
- `robots.txt` — правила для поисковых систем
- `favicon.ico`, `favicon-*.png`, `apple-touch-icon.png`, `icon-*.png` — набор
  иконок сайта: знак во вкладке браузера, в закладках, в поиске Google и в
  ярлыке «на экран Домой» на телефоне
- `.nojekyll` — пустой файл-флаг, обязательный для GitHub Pages (см. ниже)

Сайт самодостаточный: 16 моделей в каталоге, фильтры, поиск, сортировка,
калькулятор цены по размерам — всё работает прямо в браузере.

## Установка на хостинг Бегет (beget.com) — 10 минут

Бегет — крупный российский хостинг (с 2007 г.), поддержка 24/7, панель на русском.
Для этого сайта хватает самого простого тарифа виртуального хостинга.

### Шаг 1. Регистрация и тариф

1. Зайдите на `beget.com` → «Создать аккаунт» (нужны ФИО, e-mail, телефон).
2. Выберите **виртуальный хостинг, тариф «Blog»** (~420 ₽/мес при оплате за год —
   12 ГБ, до 5 сайтов; этого более чем достаточно). Первые **30 дней — бесплатно**,
   карту привязывать не нужно.
3. Сразу после регистрации у сайта уже есть бесплатный технический адрес вида
   `ваш-логин.beget.tech` — сайт можно открыть и проверить ДО покупки домена.
4. Свой домен (например, `sevural.ru`) покупается там же, в разделе «Домены»
   (или переносится от текущего регистратора), и прикрепляется к сайту в разделе
   «Сайты» — пункты «Прикрепить домен». SSL-сертификат (замочек https) выпускается
   бесплатно автоматически.

### Шаг 2. Загрузка сайта (через файловый менеджер панели)

1. В панели управления откройте раздел **«Файловый менеджер»** (он откроется
   в корне аккаунта: папки `ваш-логин.beget.tech`, `mail`, …).
2. Зайдите в папку сайта → **`public_html`** (именно сюда, это корень сайта).
3. Удалите оттуда служебный файл-заглушку `index.html`, если он есть.
4. Нажмите кнопку **«Загрузить файлы»** и загрузите архив с сайтом (ZIP).
5. Щёлкните по загруженному ZIP → **«Распаковать здесь»**.
6. Внутри архива лежит папка `roloshtory-site`. Зайдите в неё, выделите всё
   (Ctrl+A) → «Вырезать» → вернитесь в `public_html` → «Вставить».
   В итоге в `public_html` должны лежать: `index.html`, папки `_next`, `images`,
   `robots.txt` и README (саму пустую папку `roloshtory-site` удалите).
7. Откройте `ваш-логин.beget.tech` (или ваш домен) — сайт работает.

> Альтернатива: FTP-клиент (FileZilla) — хост `ftp.beget.com`, логин/пароль = от
> панели. Или попросите поддержку Бегета помочь с загрузкой — отвечают быстро.

### Шаг 3. Подключите приём заявок (см. раздел ниже)

Это единственное, что нужно настроить вручную, — 5 минут через Formspree.

## Загрузка на GitHub Pages — обязательно прочитайте

GitHub Pages (бесплатный хостинг прямо на github.com) имеет важную особенность:
по умолчанию он прогоняет сайт через генератор **Jekyll**, а Jekyll **удаляет
все служебные папки, чьё имя начинается с подчёркивания**. Стили, скрипты и
шрифты сайта лежат именно в такой папке — `_next/`. Если файл `.nojekyll`
отсутствует, страница загружается без стилей: тексты съезжают, блоки липнут
друг к другу, картинки встают не на место — именно это выглядит как
«работает некорректно, словно стили не работают».

Файл `.nojekyll` уже лежит в архиве — он отключает Jekyll, и все папки
загружаются как есть. Если вы загружали сайт на GitHub раньше, без этого
файла, исправить можно за минуту **без повторной загрузки**:

1. Откройте свой репозиторий на github.com.
2. Нажмите **«Add file» → «Create new file»**.
3. В поле имени файла введите `.nojekyll` (с точки, всё с маленькой буквы).
   Содержимое оставьте пустым.
4. Внизу нажмите **«Commit changes»**.
5. Подождите 1–2 минуты, пока GitHub пересоберёт сайт, затем откройте
   страницу сайта и обновите её с обходом кэша: **Ctrl+Shift+R**
   (на Mac — Cmd+Shift+R).

Требования к размещению на GitHub Pages:

- файлы сайта должны лежать **в корне репозитория**: `index.html`, папки
  `_next` и `images`, `.nojekyll` — рядом, а не внутри вложенной папки
  (если загрузили папку `roloshtory-site` целиком, перетащите её содержимое
  на уровень выше и удалите пустую папку);
- **Settings → Pages**: Source «Deploy from a branch», Branch — `main`,
  папка — `/ (root)` → Save;
- сайт откроется по адресу `https://ваш-ник.github.io/имя-репозитория/`;
- проверить результат: нажмите **F12 → Console** — до исправления там красные
  ошибки 404 у файлов `_next/...`, после — их быть не должно.

> Заявки из форм на GitHub Pages подключаются так же, как на любом другом
> хостинге — через Formspree (раздел ниже): одна строка в `index.html`.
> Для постоянной работы магазина в РФ надёжнее выбрать Бегет — GitHub Pages
> из России может открываться медленно, а GitHub в отдельные периоды
> ограничивает доступ.

## Как обновить сайт (залить новую версию поверх старой)

Когда появится обновлённый архив, менять репозиторий можно **без удаления
старых файлов**. Все важные файлы (`index.html`, картинки, `sitemap.xml`,
`robots.txt`, `CNAME`, `.nojekyll`) носят те же имена и перезапишутся сами.
Старые служебные скрипты с длинными именами вида
`_next/static/chunks/8a682…js` останутся лежать, но ни на что не повлияют —
новый `index.html` на них не ссылается.

Простой порядок (рекомендуется):

1. Распакуйте новый архив на компьютере.
2. Откройте репозиторий на github.com → **Add file → Upload files**.
3. Откройте распакованную папку `roloshtory-site`, выделите нужные файлы
   и папки и перетащите их в зону загрузки. GitHub принимает **не больше
   100 файлов за один приём**, поэтому грузите в несколько заходов:
   - приём 1: папка `product` (16 карточек — если не влезает, двумя половинами);
   - приём 2: папки `images` и `_next`;
   - приём 3: папки `catalog`, `about`, `contacts`, `admin`, `404` и все
     оставшиеся файлы корня — **`index.html` перетащите последним**.
4. Каждый приём завершайте кнопкой **Commit changes**.
5. Через 1–3 минуты GitHub Pages пересоберёт сайт. Откройте его с обходом
   кэша (**Ctrl+F5**) и проверьте: главная, `адрес/catalog/` и `адрес/sitemap.xml`
   открываются в новой версии.

Старые ссылки вида `сайт/#/catalog` продолжат работать: при открытии
они автоматически перекидывают на новые адреса.

Если хочется идеально чистый репозиторий (без старых служебных файлов):

- **Вручную** — в веб-интерфейсе кнопки «удалить всё разом» нет: заходите
  в каждую папку, отмечайте файлы галочками → **Delete files → Commit**.
  Это долго (файлов много и они в разных папках) и не обязательно.
- **Через ассистента** — дайте временный GitHub-токен (Fine-grained,
  срок 7 дней, доступ только к репозиторию сайта, право Contents:
  Read and write): старое будет удалено и новое залито одним обновлением,
  после чего токен удаляется на той же странице
  (Settings → Developer settings → Fine-grained tokens).

## Sitemap и поисковики (Яндекс, Google)

В архив уже включён полный SEO-комплект под архитектуру «настоящих страниц»:

| Файл | Что делает |
|------|------------|
| `sitemap.xml` | Карта сайта: **20 страниц** — главная, каталог, 16 карточек товаров, «О компании», «Контакты» + **73 фотографии с названиями** (помогает попасть в Яндекс/Google Картинки) |
| `sitemap.txt` | Плоский список 20 адресов — для простых краулеров |
| `robots.txt` | Правила обхода + директива `Sitemap:` с адресом карты |
| canonical + OpenGraph в HTML | У каждой страницы свой адрес, заголовок и превью на домене `xn--72-6kc3bemgo1a.xn--p1ai` (рулонка72.рф) |
| JSON-LD на каждой странице | Главная — LocalBusiness + ItemList + FAQ; каталог — ItemList; карточка товара — Product с ценой и рейтингом |

Каждый товар теперь имеет собственный адрес вида `/product/bambukovaya-eko-kuhnya/`
со своим заголовком («Бамбуковая «Эко Кухня» — рулонные шторы от 3 990 ₽/м² в Тюмени»)
и описанием — поисковик показывают карточку по конкретному запросу, а не только главную.

Проверка после заливки: откройте в браузере `https://ваш-адрес/sitemap.xml` —
должен показаться XML-список страниц и фото; `https://ваш-адрес/robots.txt` — короткий текст.

### Добавить сайт в Яндекс.Вебмастер (для .рф — самое важное)

1. Откройте `webmaster.yandex.ru` → «Добавить сайт» → введите адрес сайта.
2. Подтверждение прав: выберите способ «HTML-файл» → скачайте предложенный файл
   `yandex_…html` → загрузите его в корень репозитория/хостинга (рядом с index.html).
3. После подтверждения: раздел **Индексирование → Файлы Sitemap** → добавьте
   `https://ваш-адрес/sitemap.xml`.
4. Ускорить первый обход: **Индексирование → Переобход страниц** → укажите адрес главной.

### Добавить сайт в Google Search Console

1. Откройте `search.google.com/search-console` → «Добавить ресурс» → «URL-префикс».
2. Подтвердите права (файл HTML — так же, как для Яндекса).
3. Меню **Sitemaps** → введите `sitemap.xml` → «Отправить».

**Важно:** адреса в sitemap построены под домен рулонка72.рф. Если домен ещё не
подключён к хостингу — сначала подключите его (см. ниже), иначе поисковики
получат несуществующие ссылки.

### Подключение домена рулонка72.рф к GitHub Pages (когда будете готовы)

1. В корне репозитория создайте файл с именем `CNAME` (без расширения), внутри
   одна строка: `xn--72-6kc3bemgo1a.xn--p1ai`
2. У регистратора домена пропишите DNS-записи:
   - `A` → `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`
   - (опционально для www) `CNAME` → `ваш-ник.github.io`
3. В репозитории: Settings → Pages → Custom domain → введите домен → Save.
4. Через 10–30 минут, когда DNS обновится, включите **Enforce HTTPS**.
5. Проверка: сайт открывается по `https://xn--72-6kc3bemgo1a.xn--p1ai/` (и по
   `https://рулонка72.рф/` — это тот же адрес, браузер сам переводит).

Внимание: между шагом 1 и обновлением DNS сайт по старому адресу github.io
может временно не открываться — это нормально, после настройки DNS всё вернётся.

## Как открыть сайт на своём компьютере

1. Распакуйте архив (правый клик → «Извлечь всё»).
2. Откройте папку `roloshtory-site` и **дважды щёлкните `index.html`** —
   сайт полностью откроется в браузере: каталог, карточки, калькулятор, фильтры.
3. Переходы по разделам работают и локально: в адресной строке будут появляться
   адреса вида `catalog/index.html` — это нормально для локального просмотра,
   на хостинге те же страницы открываются по чистым адресам `/catalog/`.
4. Единственное отличие от «настоящей» версии — заявки из форм не отправляются:
   посетитель увидит подсказку «Позвоните нам: …» (это же происходит на хостинге,
   пока не активирована форма FormSubmit из раздела ниже).

Версии файлов собраны с относительными путями, поэтому архив один и тот же —
и для компьютера, и для хостинга. Сайт теперь состоит из папок
(`catalog/`, `about/`, `contacts/`, `product/…`) — при загрузке на хостинг
переносите ВСЁ содержимое целиком, сохраняя структуру.

## ВАЖНО: настройте приём заявок (5 минут)

В статической версии нет серверной части, поэтому заявки из форм
(«Бесплатный замер», «Оформить заявку») нужно направить во внешний сервис.
Пока это не сделано, при отправке формы посетитель видит подсказку
«Позвоните нам: …» — сайт при этом полностью работает, ничего не ломается.

### Вариант А. Formspree — проще всего (бесплатно до 50 заявок/мес)

1. Зарегистрируйтесь на `formspree.io` → «New form» → получите адрес вида
   `https://formspree.io/f/abcdwxyz`.
2. Откройте `index.html` в любом текстовом редакторе (подойдёт даже Блокнот),
   найдите тег `<head>` и сразу после него добавьте одну строку:

   ```html
   <script>window.LEADS_ENDPOINT = "https://formspree.io/f/abcdwxyz";</script>
   ```

3. Сохраните и загрузите `index.html` на хостинг. Заявки будут приходить
   на вашу электронную почту.

### Вариант А2. FormSubmit — уже встроен в этот архив

В статическую версию уже вшит приём заявок через сервис `formsubmit.co`:
обе формы («Бесплатный замер», «Оформить заявку») настроены отправлять
заявки письмом на `sevural70@mail.ru`. **Ничего добавлять в код не нужно** —
просто загрузите сайт на хостинг и сделайте активацию:

1. Загрузите сайт на хостинг (или GitHub Pages) и откройте его.
2. Отправьте **тестовую заявку** через любую форму сайта.
3. На `sevural70@mail.ru` придёт письмо «Activate form» — кликните ссылку
   внутри. Это одноразовая защита сервиса от злоупотреблений.
4. Готово: все последующие заявки будут приходить письмами с темой
   «Заявка с сайта «Северный Уралец»» и полями: имя, телефон, комментарий,
   товар. Проверьте папку «Спам» и отметьте письмо как «Не спам».

Если понадобится сменить почту для заявок или перейти на другой сервис
(Formspree, Telegram) — откройте `index.html`, найдите в начале строку
`window.LEADS_ENDPOINT=...` и замените адрес:

```html
<script>window.LEADS_ENDPOINT = "https://formsubmit.co/ajax/НОВАЯ-ПОЧТА@mail.ru";</script>
```

Нюансы FormSubmit: истории заявок в интернете нет (только почта); сервис
зарубежный.

### Вариант Б. Свой endpoint (Telegram-бот, Google Таблица, CRM)

Сервис должен принимать `POST` с JSON:

```json
{ "name": "Имя", "phone": "+7...", "comment": "...", "product": "...", "source": "..." }
```

и отвечать `{"ok": true}`. Адрес указывается той же строкой из Варианта А.

## Хотите редактировать сайт онлайн (цены, фото, тексты)?

В статической версии контент «вшит» в файлы. Есть **полная (серверная) версия**
этого сайта — с базой данных и встроенной админ-панелью `#/admin`:

- вход по паролю с любой страницы: `ваш-домен/#/admin` (внизу сайта «Вход для владельца»);
- товары: цены, скидки, описания, характеристики, фото (загрузка с компьютера),
  порядок, добавление и удаление — всё меняется мгновенно, без программиста;
- контакты, тексты главной, FAQ, отзывы — тоже редактируются.

Для неё нужен **VPS** (виртуальный сервер). На Бегете: «Облачные серверы» →
готовый образ **Node.js** (Ubuntu + Node.js + PM2 + Nginx, от ~27 ₽/день + 5 ₽/день
за IP; при создании сразу указывается домен и автоматически ставится SSL).
Дальше по SSH:

```bash
# загрузить исходники проекта в /var/www/html (по SFTP), затем:
cd /var/www/html
npm install
npm run build
sudo -u nodejs pm2 start npm --name sevural -- start   # или node .next/standalone/server.js
```

Пароль админки задаётся переменной окружения `ADMIN_PASSWORD` (по умолчанию
`rolltex-admin` — обязательно смените). На виртуальном (не VPS) хостинге
админ-панель недоступна: сайт сам честно сообщит об этом на странице входа.

## Как изменить цены, тексты, контакты без админки

Контент сайта (16 товаров, цены, отзывы, FAQ, этапы работы, реквизиты) хранится

```bash
npm run build:static
```

Если реквизиты изменятся — отредактируйте блок `CONTACTS` в `src/data/products.ts`

## Хостинг для аудитории из России

Для РФ-аудитории практичнее российские хостинги (Beget, Timeweb, reg.ru) —
инструкция по Бегету выше подходит напрямую. У зарубежных платформ (Netlify,
Vercel) стандартные адреса из РФ могут открываться медленнее; при подключении
собственного домена разница исчезает.
